# Security

## Who can act

Local handoff previews run without desktop access. On macOS the public CLI, MCP tool and installed `jev-run` share a supervisor. Input requires explicit act mode, an expected foreground, and consent from `jev-brain consent` in an interactive terminal. Revoke consent by removing `~/.config/jev-brain/consent.json`.

Before starting an executor, including for `--arm`, the parent reads macOS accessibility (AX) metadata in its own process. It binds the app PID to its bundle identifier and reads the front window, document URL and focused element’s role, subrole, title, description and placeholder. For a named control the parent resolves its exact title or description in the same foreground and checks its metadata before launch. The parent retains this observation and the named target’s metadata. After runner lookup, the launch worker builds the command and environment, then repeats the preflight immediately before requesting the helper. On helper readiness and again at executor dispatch, the parent repeats the bounded checks and requires equality with that approval. Transport errors, unreadable values, a missing role, window title or identity, and focus changes cause refusal. Optional attributes may be absent when AX explicitly reports them as unsupported or empty.

Only TextEdit, Notes, Finder and Calendar are eligible native apps. A missing or mismatched browser URL fails the expectation check. Even an exact HTTP(S) URL leads to refusal because this release has no trusted browser-origin approval mechanism. This applies to every browser-backed step, including management consoles at regional or private hostnames.

The sensitive-surface classifier normalizes compatibility characters and case, checks known clients and sensitive terms, and refuses residual non-ASCII text, hidden control characters and unresolved URL encodings. Ordinary localized interfaces can therefore be refused. A private document with innocuous metadata can still look ordinary. Never pass credentials or private communications. Arguments can be visible to other processes under your account.

The adapter independently resolves the control and rechecks focus at input time. A press requires a unique exact title or description among elements exposed through the focused window’s AX children. The search retains distinct references at identical coordinates and counts offscreen matches. A failed read, a search over 512 elements, a missing press action, or a centre hit-test that reaches another element stops the step. On entry the bundled backend compares its foreground and named target with fingerprints supplied by the parent. One final gate rechecks the foreground, focused window and field, ownership, the unique button reference, role, labels, available actions and centre hit, or the focused text field and its empty value. It samples the pointer abort corner again. The press reports the observed title, falling back to the matching description. The write uses selected-text insertion in a verified empty field and checks the value afterward.

AX reads on independent objects can return a mixture of states. The gate requires a synchronous revision covering every guarded change through the end of those reads. Only the in-memory test desktop provides one. The pinned macOS backend therefore returns `unverifiable input` and sends zero presses or writes. There is no CLI, MCP or environment option to supply a revision. Even a consistent final gate cannot protect the interval before OS delivery. The launcher has an analogous interval between observing focus and requesting process creation or executor dispatch. [Apple AX element API](https://developer.apple.com/documentation/applicationservices/axuielement_h) Across processes the comparison uses reported metadata and PID. Two windows or controls that expose identical metadata can be indistinguishable. Within the adapter the final checks also compare live AX references. Pixel-only controls and content omitted by the accessibility provider cannot be verified. A timeout, interruption or lost acknowledgement can follow a mutation. Inspect the app before retrying.

## Local files and executors

Act attempts require a confirmed initial append and filesystem sync before observation or launch. The initial and final records contain a UTC timestamp, random call ID, combined argument length, a known bundle ID when verified, and a fixed outcome code. The program keeps requests, control labels, literal text, window titles, URLs and backend output out of its files. The command returns results to its caller, which may retain them. If the final append fails or exceeds the deadline, the caller receives `audit indeterminate`, the preceding `step_outcome` and its step count. Storage may finish an outstanding append after the response. A crash or storage failure can leave a call with only its initial record. POSIX consent and audit files must be user-owned, single-link regular files with no group or other permissions. Newly created files use mode 0600. The same account can edit its own log and consent file.

The supervisor sets one 30-second monotonic deadline before validation. It bounds waiting for audit storage and native reads inside the parent. Up to four workers handle preflight and audit I/O. A separate pool of up to four startup slots bounds outstanding child processes and stalled constructors. Each constructor starts an isolated Python helper with site initialization disabled. The helper reports readiness on a private status pipe and waits for the supervisor’s grant. It then requests dispatch and waits for a second authorization. Only the supervisor with a process handle can send either byte. Both sides check the same deadline. A timeout or interruption before dispatch authorization leaves the executor unstarted. The status descriptor closes on exec. If exec fails, the helper reports that failure on the descriptor and the caller gets `started=false` and zero steps. If startup cannot be confirmed after dispatch authorization, `started` and `steps` can both be null. Cleanup can finish after the response if the OS is still creating or reaping the helper. After dispatch authorization, interruption can leave the input outcome uncertain. The bundled Python backend runs with `-I` in the installed environment, excluding the working directory, user site and `PYTHONPATH` from helper discovery. Install both packages in the same trusted virtual environment. A trusted editable installation includes its source checkout.

The supervisor caps the executor reply at 64 KiB and closes pipes on termination. The four input strings are limited to 4,096 characters each. MCP reads newline-delimited frames in bounded chunks with a 2,000,000-byte limit and ASCII-escapes response JSON. Executor-backed modes require macOS. Windows and Linux support the local preview.

Only use a trusted `jev-run` on the host’s `PATH`. A replacement executable has the host’s permissions, controls its own artifacts, and must enforce the window guard at input time. The supervisor can withhold dispatch. Once a replacement starts, its own code controls any further observations and input. The included adapter uses local accessibility elements and stores no screen images. Upstream’s full classifier loop has a different data flow, sends state to its configured providers, and writes its own run folder. [Upstream documentation](https://github.com/awlevin/typesafe-computer-use)

## Config and mock server

`jev-brain install` reports the config path and proposed action. With `--yes` it adds a missing server under the current home. Existing jev-brain and systemone entries retain their settings. The installer checks server entries, MCP policy fields and project or profile restrictions. An alias keeps its original restrictions when the effective program is a recognized console entry, a current or legacy Python MCP module, or a package-qualified path to either shipped `mcp_server.py`. The parser follows literal `env` and `uv run` commands, accounts for an explicit working directory, and stops at the selected Python script or module. For filesystem aliases, the installer resolves the executable with the entry’s PATH and working directory, follows symbolic links and compares file identities against current and legacy entries. It falls back to the inherited PATH for entries that omit it. An unknown working directory for a relative lookup, a missing file, a hard link of unknown identity, inline code, shell launchers and unrecognized wrapper flags can require manual review. The diagnostic identifies the entry without printing its arguments or environment. The installer can identify declared entry points only. It cannot inspect what arbitrary application code runs internally. A relevant or ambiguous policy also requires a manual edit. A new TOML table must reparse to the expected key path and preserve the rest of the parsed document. Incompatible layouts require a manual edit.

Keep the mock HTTP service on its default loopback address. Remote binding requires `--allow-remote`. The service offers health and fixed closed-question answers. Desktop input is available through the CLI and local stdio MCP. Treat question text and responses as untrusted data. Keep secrets out of mock requests. HTTP request bodies are excluded from server logs.
